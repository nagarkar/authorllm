Quick reference

Proposal triage loop

Use this when new manuscript material conflicts with settled conceptual knowledge and AuthorLM opens a proposal against the graph.

The operator loop

List the queue→Inspect settled note→Inspect manuscript evidence→Judge definition vs role→Dismiss or adopt→Reason becomes evidence

CLI spine

NeedCommandWhy
See open conflictsauthorlm proposal list -m SMSTTDFind the id prefix and proposal kind.
See the settled conceptauthorlm concept show "Nothing" -m SMSTTDThe live graph note is the source of truth.
See manuscript evidencerg -n "Nothing is" authorlm/manuscripts/SMSTTDCheck whether the proposal matches what the book actually says.
Record a rejectionauthorlm proposal dismiss pr-58e88 -m SMSTTD --why "..."The reason is recorded as evidence.
Record an adoptionauthorlm proposal accept pr-58e88 -m SMSTTDUse only when the new note is genuinely better law.

The critical distinction

A concept note should define what the concept is, not merely narrate what the concept does in the book. “Nothing is the clasp of paradoxes” is a definition. “Nothing is the starting point of the book's metaphysics” is a role description.

Current limitation

The present CLI exposes queue review interactively and verdicts by id prefix, but it does not yet expose a clean non-interactive proposal show <id> read path. Operator discipline still holds: prefer the public CLI, and if the surface is missing, treat that as a product gap rather than silently normalizing direct database reads.

What the learning loop already does

When you dismiss a proposal, AuthorLM records evidence and suppresses an exact verbatim repeat of the same payload. It does not yet auto-decline semantically similar paraphrases based on your prior reasons.
