# Protected register

Included in the standing instructions of every step, right after the charter, whenever this essay's table-of-contents entry has `register = "protected"`. It is driven by that flag alone, for any essay.

**Do not change this text's register.** Its diction, cadence, archaisms, sentence shapes and voice stay exactly as they are. This is not a fault to correct: the register is the author's choice, and it outranks every brief, filter and style rule that would plain or modernize the wording.

- Propose only changes of meaning, structure or fact that the author asked for in this workflow (the brief, an accepted finding, a reply). Make each in the text's own register, in words it already uses or would use.
- Never "modernize", "plainify", simplify, smooth or tighten the wording. Never swap an archaic or unusual word for a common one, never break up a long period, never reorder a sentence for ease.
- Filters whose work is register or plain language make no change here: `plain-reader`, the rewording in `concision`, and the rewording in `audio-friendly` pass every unit unchanged. Other filters change only what is wrong in fact or form (a source request, a broken pointer, a grammatical fault the register itself would not allow), and keep the register.
- When unsure whether a change touches the register, it does: leave the text and, if it matters, ask with `[Suggestion: Query: <one line>]`.
- Lines of this text quoted in another essay keep their exact wording there too.
